# 🧠 How I Work

I try to keep my development approach simple:

### 01 — Understand the Problem

Before writing code, I try to understand **what problem I'm actually solving**.

### 02 — Break It Down

Large problems become easier when divided into smaller, manageable pieces.

### 03 — Build Practically

I prefer working solutions over unnecessary complexity.

### 04 — Learn While Building

If I don't know something, I research it, experiment with it and implement it.

### 05 — Improve

I believe the first working solution doesn't have to be the final solution.
